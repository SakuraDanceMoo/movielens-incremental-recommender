# 阶段四实验记录

日期：2026-10-27（Asia/Hong_Kong）
数据：MovieLens 32M，阶段一训练正反馈与冻结候选集
复现入口：`run_phase4.py`

## 实验设置

按事件时间回放训练集评分不低于4的全部正反馈。事件游标按 Parquet 原始 `rowId` 稳定排序键顺序消费；每条事件增量更新累计电影热度、30天滑动窗口热度、用户正反馈数及用户类型画像。事件时间推进时清除窗口外热度。每位用户在阶段一首个测试时间前生成推荐，使用同一测试正样本和100个固定负样本，测试标签不进入流状态。

推荐分数为累计正反馈数加权窗口热度和类型画像项。窗口为30天，窗口权重0.1，画像权重0.2。算法、完整参数和幂等游标边界见 [config.json](../config.json)。游标仅在本次内存回放中幂等；没有持久化检查点或进程崩溃恢复。

环境为 Python 3.11.16、Polars 2.0.0、NumPy 2.4.6、20个逻辑CPU的 Windows 单机，开始时可用内存17.97 GiB；依赖位于 `D:\AgentProject2026\.venv` 并由 uv 管理。此基准不包含消息队列、网络、存储和检查点 I/O。

## 结果

完整消费 12,905,652 条训练正反馈，覆盖191,007位固定候选用户，耗时约67.08秒（含输入读取和排序），回放及候选评估约55.91秒，吞吐约230,846条/秒。事件状态更新延迟均值0.00332ms、P50 0.0029ms、P95 0.0045ms、P99 0.0101ms、最大9.9818ms，低于100ms目标。查询watermark的窗口维护P99为0.0199ms；候选打分单独统计的P99为0.1063ms。

NDCG@10为0.864000，阶段一同用户基线为0.866186，相对下降0.252%。Recall@10为0.841287，基线为0.845159，相对下降0.458%。因此事件更新延迟目标达成，但推荐质量无下降目标未达；本阶段不宣称效果通过。

## 独立验证与限制

独立脚本复算了191,007位用户的宏平均指标和1,910,070条Top10结果，检查候选归属、唯一电影、名次和分数排序。五个事件时间点的源游标、watermark、滑动窗口起点、窗口事件数、活跃电影数和画像用户数均通过独立复算；重复消费已处理游标不改变状态。详情见 [verification.json](verification.json)，运行数据见 [stream_metrics.json](stream_metrics.json)，延迟分布见 [streaming_latency.png](../curves/streaming_latency.png)。

这只是单机内存回放，不证明 Kafka/Flink/Spark Streaming 的端到端延迟、持久化恢复或多节点伸缩。下一步应在独立验证集上选择窗口和融合权重，再用冻结测试集作一次最终评估；在效果恢复至基线前，不满足路线的质量验收目标。
